# ユーザー登録画面（UI-04）

- アプリURL：`/register#token=<token>`
- 画面イメージ：[asset/register.html](../asset/register.html)
- フロー：[登録・LINE連携](../design/registration.md)、API：[API仕様](../api/README.md)

## 初期表示・入力

未認証でも表示し、ログイン済みでも一覧へ自動転送しない。フラグメントからトークンをメモリへ読み、`POST /auth/registration/validate`へ`registration_token`を送る。有効なら期限を日本時間で表示し、入力を許可する。確認中・確認失敗時は登録不可。トークン欠落はAPIを呼ばず無効URLを表示する。トークン・LINEユーザーIDは画面に表示しない。

| HTML要素ID | 要素 | 挙動 |
| --- | --- | --- |
| registration-form | 登録フォーム | Enter・ボタンで送信。本人が設定するID・パスワードの2項目。認証済みなら「登録後は新しいユーザーでログインします」と案内 |
| login-id | ログインID | 必須、1〜100文字、autocomplete=username。前後空白・大小文字を区別し、値を正規化しない |
| password | パスワード | 必須、UTF-8で8〜72バイト、autocomplete=new-password。送信失敗時・離脱時に消去 |
| register-button | 登録 | 有効URLかつ入力が妥当なとき送信可能。送信中は入力とボタンを無効化 |
| registration-error | エラー | role=alert。入力エラー・ID重複・URL無効・通信失敗・試行制限を表示 |
| registration-status | 状態 | aria-live。確認中・送信中・完了を表示 |
| registration-expires-at | 有効期限 | 有効性確認で取得したexpires_atを日本時間で表示 |
| retry-button | 確認の再試行 | 初期確認の通信失敗から有効性確認を再実行。登録POSTを自動再送しない |
| recovery-note | 復旧案内 | URL無効・期限切れは「LINEトークで『登録』と送信してください」。使用済みの可能性があればログインも案内 |
| login-link | ログインへ | `/login`へのリンク。入力したID・パスワードやトークンをURLで引き継がない |

## 送信・失敗時

`POST /auth/register`に`registration_token`・`login_id`・`password`を渡す。201ならSessionをメモリ保持し、旧ユーザーの一覧・設定・未保存データ・未完了要求を破棄する。トークンを破棄して`/assets`へ置換遷移する。登録直後は銘柄0件・初期通知率となる。

409はID重複を表示し、ID・有効トークンを保持、パスワードを消去する。410は無効・期限切れ・使用済み・失効済みを共通の案内にし、入力・送信を不可にする。APIからこれらの原因を区別する情報は取得しない。429はRetry-Afterに基づく待機後に確認し直す。確認時点で有効でも送信前・送信中に失効し得ることを扱う。

通信中断・503などで登録成否が不明なら登録フォームの再送を止める。セッション確認で入力したIDのログインが確認できれば一覧へ進み、それ以外は「登録が完了している場合は、入力したID・パスワードでログインしてください。未完了の場合はLINEで『登録』と送信してください」と案内する。初期確認失敗と登録成否不明は別状態にする。

## HTML見本

正常・確認中・確認失敗・送信中・ID重複・無効・期限切れ・使用済み・再発行済み・通信失敗（成否不明）・試行制限・完了を切り替えられる。期限切れなどは説明用状態で、実APIはすべて共通の410を返す。通常のフォーム送信は入力規則を確認して完了を表示し、一覧HTMLへ進む。再試行は確認だけを模擬する。実際のLINE照合・API・Cookie・DB保存は行わない。

PC 1440×900・スマートフォン390×844で横はみ出しなく表示する。ラベル、aria-live/alert、無効化状態、キーボード送信、エラー項目へのフォーカスを確認する。
