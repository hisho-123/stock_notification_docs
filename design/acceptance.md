# 受け入れ条件・検証シナリオ

製品実装時の受け入れ条件と、本仕様書・HTMLを確認する条件を定義する。通知・外部価格取得はモックを用い、実ユーザーへの送信なしで検証する。例示する価格は仮の値。

## 文書・画面イメージ

| ID | 確認 | 合格条件 |
| --- | --- | --- |
| DOC-01 | READMEと相互リンク | 参照先が存在し、全画面HTMLとOpenAPIへ到達できる |
| DOC-02 | 項目・型・状態 | ER・API・UIの項目名、価格文字列、日時、NULL、通知設定が一致 |
| DOC-03 | OpenAPI | 3.0.3としてパース・検証でき、参照が解決し、例示JSONが各スキーマに適合 |
| UI-01 | 3画面の表示 | PC 1440×900、スマートフォン390×844でページ全体の横はみ出し・文字の重なりなし。一覧テーブルだけ横スクロール可 |
| UI-02 | 状態切替 | 各HTMLの確認用パネルで通常・読み込み・該当する空/失敗/処理中状態を表示できる |
| UI-03 | 操作 | サンプル追加・検索・数値ソート・停止/再開・削除確認/取消/確定・通知率編集が動作する |

## 通知・同時処理・障害

| ID | 条件 | 期待結果 |
| --- | --- | --- |
| M-01 | H=100、P=90.0001と90 | 前者は未通知、後者は10%。表示丸めに判定が影響されない |
| M-02 | H=100、P=73、未通知 | 25%について1通のみ、L=25 |
| M-03 | 20%通知後に95→80→100 | 再通知なし、L=20保持 |
| M-04 | 20%通知後に110→99 | 110でH更新・L=null、99で10%通知 |
| M-05 | L=20、設定を[5,15,25]へ変更、P=80→75 | 80は通知なし、75で25%通知 |
| M-06 | LINE失敗 | L保持、取得価格・日時とNOTIFICATION_FAILED保存。次回の最新価格で再判定 |
| M-07 | FMP失敗 | 価格・最高値・通知済み率保持、確認時刻とPRICE_FETCH_FAILEDを保存。他銘柄処理継続、終了1 |
| M-08 | 正常処理へ復帰 | last_error_code=nullに戻る |
| M-09 | DB保存失敗 | 対象のトランザクションをロールバック、終了1。LINE受付後なら重複リスクを確認 |
| M-10 | 監視コマンドの同時起動 | advisory lock取得側だけ処理、もう一方は正常スキップ。通常の二重送信なし |
| M-11 | 価格取得中に停止・削除 | 行ロック取得後に再確認し、停止・削除済みなら送信しない |
| M-12 | LINE送信中に停止・削除 | 完了まで行ロックを待つ。停止・削除前の送信は成立し得る |
| M-13 | 実行途中に共通設定を変更 | 実行開始時の配列を全対象で使用。次回から新配列 |
| M-14 | 登録0件・休日の同じ価格 | 正常終了0、不要な通知なし |

## 認証・運用

| ID | 条件 | 期待結果 |
| --- | --- | --- |
| S-01 | 未認証・期限ちょうど・期限後 | 全保護APIは401。画面はログインへ遷移 |
| S-02 | ログイン成功・ログアウト | Cookie属性・24時間期限を満たす。ログアウト後の旧Cookieは使用不可 |
| S-03 | 他Origin・Origin欠落、変更系CSRF欠落/不一致 | 403、DB変更なし。ログインもOrigin確認 |
| S-04 | 15分内に5回認証失敗後の再試行 | 429、Retry-After。窓の経過後は再試行可能 |
| S-05 | JSON以外・未知項目・不正ID | 415または400。処理しない |
| S-06 | 秘密値を含む外部障害 | 応答・ログにキー、トークン、SQL、レスポンス本文なし |
| S-07 | スケジュール設定 | 日本時間07:00に起動。UTCなら前日22:00との対応を確認 |
| S-08 | 設定欠落・DB接続不可 | 実行を失敗させ、既定値で運用を継続しない |
| S-09 | セッション掃除・DB復元 | 期限切れは未掃除でも拒否。復元後は全セッション削除 |

本仕様書の確認結果は[verification.md](verification.md)に記録する。
