# 機能仕様

## 利用者・対象

利用者は設定済みの管理者1人。株と指数を同じ「監視対象」として扱い、種別の手入力は設けない。銘柄コードはFMPの識別子を使用する（例：`AAPL`、`^GSPC`）。APIの取得可否・価格の更新頻度は対象と契約に依存する。

## 登録

1. 一覧画面で`code`のみ入力する。前後の空白を除去し、ASCII英字を大文字化する。正規化後は1〜64文字で、途中の空白・制御文字は不可。
2. 同一の正規化済みコードが登録済みなら`409 ASSET_ALREADY_EXISTS`を返す。停止中の対象も重複に含める。
3. FMPの`GET /stable/quote`で`symbol`を指定し、一致するレコードの`price`と`timestamp`を取得する。名称は文字列の`name`の前後空白を除去し、先頭200文字までを使用する。取れない場合や空白だけの場合はコードを使用する。
4. 有限かつ正の価格と有効なtimestampが取得できた場合にだけ登録する。最高値・最終取得値を取得価格、最終通知済み率を`null`にする。[鮮度判定](monitoring.md)で10日未満なら監視中・エラーなし、240時間以上前なら停止中・`PRICE_DATA_STALE`として警告付きで登録する。どちらも取得日時・最終確認日時は実際の取得完了時刻とする。
5. DBに保存して`201`で返す。登録操作ではLINE通知を行わない。二重送信・同時登録にもDBのユニーク制約で対応する。

一致するレコードがない場合は`422 SYMBOL_UNAVAILABLE`。無効な価格・timestampの欠落や不正・不正レスポンス・外部サービスの拒否や障害は`502 PRICE_PROVIDER_ERROR`、30秒の取得タイムアウトは`504 PRICE_PROVIDER_TIMEOUT`。失敗時は登録しない。最高値・名称は利用者が編集しない。

## 一覧・検索・ソート

`GET /api/v1/assets`は保存済みデータを返す。呼び出し時に価格を取得しない。表示件数のページングは設けない。

| 項目 | 動作 |
| --- | --- |
| 検索`q` | 前後空白を除去したコード・名称の部分一致。大文字小文字を区別しない。最大200文字。`%`と`_`は文字として検索する |
| ソート`sort` | `created_at`（既定）、`code`、`name`、`highest_value`、`latest_value`、`decline_rate`、`latest_fetched_at`、`enabled`、`last_notified_threshold` |
| 順序`order` | `asc`（既定）、`desc`。数値は文字列順ではなく数値順。日時は時刻順、監視状態は停止=false→監視中=true |
| 同値・未通知 | 同値は常に`id`昇順。未通知の`null`は昇順・降順どちらも末尾 |
| 下落率ソート | 表示丸め前の下落率で比較する |
| 更新 | 初期表示、検索、ソート、一覧更新ボタン、登録・停止・再開・削除成功時に再取得。自動ポーリングなし |

一覧項目は[DB定義](database.md)と[API仕様](../api/README.md)を参照。下落率は画面・APIで小数2桁、四捨五入（half-up）で表示する。保存する価格の精度は固定しない。

## 停止・再開・削除

- `PATCH /api/v1/assets/{id}`で`enabled`を設定する。同じ値への更新も成功。停止中は日次処理から除外し、最高値・最終取得値・取得日時・通知済み率を保持する。
- 再開による価格取得や通知はしない。次に日次処理の対象となった際に、保持した最高値と通知済み率で判定する。通常は翌日からだが、実行中の停止→再開では同じ実行で処理・通知され得る。停止期間中の値動きは補完しない。
- 削除確認にコード・名称と「再登録時は最高値と通知済み状態が新しくなる」旨を表示する。確定後に`DELETE /api/v1/assets/{id}`を実行し、物理削除する。存在しなければ`404 ASSET_NOT_FOUND`。
- 停止・再開・削除と監視処理の排他制御は行わない。監視中の操作は運用で避ける。同時実行時は停止・削除完了後の送信抑止や更新の整合性を保証しない。
- 古いデータの停滞通知が成功した対象は自動停止する。手動再開まで価格を取得しない。停滞通知失敗時は監視中を維持し、翌日の日次処理で再取得・再判定する。
- 削除後の同一コードの再登録は新しいID・取得価格・未通知状態で開始する。

## 共通通知設定

`thresholds`は1〜99の整数の配列。1〜99件、重複不可、空配列不可。入力順に関係なく昇順で保存・返却する。初期値は`[10,15,20,25,30]`。`PUT /api/v1/settings/notifications`で配列全体を置き換える。

設定変更時は、停止中の対象を含め最高値と`last_notified_threshold`を変更しない。設定から削除された値も通知済み率として保持する。例えば20%を通知済みの対象で設定を`[5,10,15,25]`に変えた場合、25%以上に到達したときだけ新たに通知する。変更時には送信せず、次の監視実行から適用する。

画面には保存前からこの動作を説明する。保存失敗時は編集内容を保持し、再試行できる。異なるブラウザからの同時保存は後にコミットされた設定を採用する。

## エラー表示

| last_error_code | 表示・意味 |
| --- | --- |
| `PRICE_FETCH_FAILED` | 「価格取得に失敗」。timestampの欠落・不正も含む |
| `NOTIFICATION_FAILED` | 「LINE通知に失敗」。下落通知または停滞通知の失敗 |
| `PRICE_DATA_STALE` | 「価格データが10日以上前」。停滞通知成功による自動停止、または警告付き停止登録 |

停止の表示とエラー表示は併記する。古いデータの検知を正常取得として扱わず、日次処理では保存済みの価格・取得日時を保持する。新規登録では古い価格を保存するが、停止状態と警告を必ず表示する。手動再開だけではエラーを消さず、鮮度確認を通過して通常の日次処理が完了した場合に解消する。

下落通知の送信失敗後は再送などの追加処理を行わず、翌日の日次実行で最新価格から再判定する。翌日に通知不要ならエラーを解消し、過去の下落を繰り越して通知しない。

一覧APIの通信失敗は銘柄単位の状態と区別し、画面全体のバナーで表示する。秘密情報や外部APIのレスポンス本文は表示しない。
