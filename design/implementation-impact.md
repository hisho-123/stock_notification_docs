# 関連実装への影響

本改訂の成果物は仕様書・OpenAPI・HTML見本。製品のGo API・Reactアプリ・DBマイグレーションは変更していない。2026-10-17に隣接リポジトリを確認した時点の実装は単一管理者向けで、以下の変更が必要。

| リポジトリ | 現状 | 必要な変更 |
| --- | --- | --- |
| stock_notification_backend | 環境変数の管理者認証、所有者なしの3テーブル、全体通知設定1行、固定LINE送信先 | 新6テーブルのマイグレーション、DBユーザー認証、セッションのlogin_id、全データ操作の所有者条件、ユーザー別通知設定 |
| stock_notification_backend | Webhook・ユーザー登録なし | 署名検証、イベント重複・順序判定、登録URL発行・再発行・失効、トークン確認・登録API、原子的な登録、LINE返信、友だち状態管理 |
| stock_notification_backend | 日次処理は全銘柄に同じ通知率・LINE送信先を使用 | ユーザー別スナップショット、users.line_user_id宛の送信、ブロック抑止・停滞時の例外、設定欠落ユーザー以外の処理継続 |
| stock_notification_frontend | ログイン・一覧・設定の3画面、Session.admin_id | 登録画面とルート・状態表示、login_idへの型・要求変更、公開登録API、登録成功時の自動ログイン・旧データ破棄 |
| stock_notification_frontend | 単一ユーザーを前提にした画面・APIスタブ・テスト | ユーザー切替時の入力・キャッシュ・未完了要求の破棄、本人のデータだけを表示する検証、登録・URL異常のUIテスト |
| 両リポジトリ | 旧設定・初期データ・9操作のAPI契約 | 環境変数・起動検証・開発手順・モック・テストを12操作の新契約へ更新し、新スキーマで開発DBを再作成 |

独立した`stock_notification_infrastructure`リポジトリは参照範囲になく、運用・配信設定はbackendのdeploy構成を確認した。WebプロセスへLINEトークン・チャネルシークレットを渡し、公開HTTPSのWebhookルートをCookie・Origin検証の対象外として署名検証へ通す必要がある。監視コマンドの固定LINEユーザーID設定は削除する。

後方互換API・旧管理者の自動ユーザー化・データ移行・ユーザー管理画面は提供しない。製品実装後に[受け入れ条件](acceptance.md)の新シナリオをモックLINE・FMPと複数ユーザーの専用DBで実行する。[実装済みテストケース](test-cases.md)と過去の[検証結果](verification.md)は旧実装の記録として保持し、新仕様の検証済み実績に数えない。
