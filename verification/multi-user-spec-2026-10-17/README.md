# 複数ユーザー・LINE登録仕様の検証（2026-10-17）

対象は仕様書・OpenAPI・静的HTML見本。関連backend・frontendの新機能を実装・実行した記録ではない。LINE・FMPへの通信、実ユーザーへのメッセージ送信は行っていない。

| 対象 | 方法 | 結果・証跡 |
| --- | --- | --- |
| OpenAPI | openapi-spec-validator 0.7.2でOpenAPI 3.0.3として検証 | 合格。12操作・15スキーマ |
| 参照・例示 | 内部参照の解決、openapi-schema-validatorで全例示を検証 | 合格。内部参照135件・例示48件 |
| API契約 | 登録要求、ID境界、旧admin_id・所有者差替・LINEユーザーIDの受渡し拒否、Webhook拡張許可をスキーマ検証 | 合格。13確認。バイト長・認可などアプリ実装による検証は含まない |
| 文書・HTML | ローカルリンクの存在、HTMLのID重複・label/ARIA参照、画面仕様の要素IDを照合 | 合格。4画面 |
| JavaScript・差分 | node --check、git diff --check | 合格 |
| 表示・操作 | Chromium（Playwright）、PC 1440×900・スマートフォン390×844、4画面の全状態と主要操作 | 合格。86確認、ページ全体の横はみ出しなし、JavaScript例外なし |
| 登録画面の目視 | 通常状態のPC・スマートフォン画像 | 入力欄・説明・ボタンの重なりなし |

[静的検証の詳細](static-checks.json)、[ブラウザ検証の詳細](browser-checks.json)、[PC画像](register-1440.png)、[スマートフォン画像](register-390.png)を参照。

ブラウザ検証は登録の無効URL・期限切れ・使用済み・再発行済み、確認／送信中、ID重複、確認失敗からの再試行、登録成否不明、試行制限、完了を含む。7バイト・75バイトの拒否、2文字8バイトと24文字72バイトの許可、ID 100/101文字の境界、登録・ログインから一覧への遷移、銘柄追加・通知設定保存の回帰確認を実行した。送信・遷移は見本内の模擬動作。

製品の複数ユーザー分離、DB制約・トランザクション、Webhook署名・重複・順序判定、LINE実返信・ブロック連携、日次通知、HTTPヘッダー、実運用スケジュールは未検証。[受け入れ条件](../../design/acceptance.md)を製品実装時に実行する。関連実装の作業項目は[実装への影響](../../design/implementation-impact.md)を参照。

再確認は各HTMLの「画面確認用」を展開し、状態を選んで行う。登録見本はトークンなしでも有効URLの状態を模擬する。実アプリのトークンなし拒否を確認したものではない。HTMLは直接開くか、リポジトリ直下で`python3 -m http.server 18743 --bind 127.0.0.1`を起動して確認できる。
