# フロントエンドのC0/C1検証（2026-10-17）

単一管理者向けのReactフロントエンド（ログイン・監視対象・通知設定）に、カバレッジ計測とテストを追加した。複数ユーザー・LINE登録の新仕様は今回の実装・検証に含めない。検証したfrontendは[96d3e9e](https://github.com/hisho-123/stock_notification_frontend/commit/96d3e9e61f7b4002b6716c0de1e6c8f90809418c)（fc5bf67からの変更）で、製品API・backendは変更していない。

## 定義と合格条件

- C0＝Istanbul Statements、C1＝Branches。ループやbool戻り値を独自に追加するbackendの計測とは定義が異なる。
- Vitestは本番src全体（起動・ルーティングを含む）の文・分岐をファイル別100%で判定。未実行ファイルも母数に含め、テスト・型宣言だけを除く。
- Playwrightは全体と重点範囲をPC・スマートフォン別、および合算で報告。重点範囲は3画面と認証・API・一覧取得・入力検証・表示・共通UIで、起動・ルーター定義・定数定義は全体値へ含める。
- Playwrightの100%は改善目標。未達率によるCI失敗は設定しないが、テスト失敗・計測データ欠落・集計不具合は失敗とする。VitestとE2Eの数値は合算しない。
- 両実行環境の変換・計測結果に基づく母数をそのまま報告する。ignore指定やカウンタ操作で100%にしない。

## E2Eで残った経路

以下はVitestで検証済み。E2Eの分母から除外せず未到達として残す。正確な行・分岐番号は生成される`coverage/e2e/combined/priority/uncovered.md`を参照。

| 経路 | 理由 |
| --- | --- |
| API・ログインの一般例外フォールバック | 通常の通信障害はAPIクライアントがApiErrorへ正規化するため、一般例外の防御経路に入らない |
| 認証Providerの破棄・取消後応答・Provider未設定 | 通常のSPA内の移動ではProviderを破棄しない。ページ全体破棄後はJS実行環境も失われる。Provider未設定は構成エラー |
| ダイアログのbusy省略 | 現行画面はbusyを明示しており、省略時の契約は共通部品テストで確認 |
| 対象なしの削除・閉じたダイアログ確定 | 非表示の確認を通常ユーザー操作から実行できない |
| ログインの処理中再送・ロック中の通知率追加 | 通常の入力・送信操作はdisabledで抑止される。フォームの防御処理は単体テストで確認 |
| 設定の遷移保留中の保存・取消後成功、古い一覧成功の破棄 | モーダル背面の操作と、取消済みfetchの成功返却は通常操作で再現できない。単体テストで状態・応答順序を制御して確認 |

通信断・不正JSON・要求取消・IME・期限切れ・ログアウト失敗・重複操作はブラウザでも再現した。通常操作で確認できる結果と、構成ミス・競合への防御処理を区別する。詳細な操作一覧と根拠はfrontendの`docs/testing.md`に記録した。

## 実行と成果物

frontendリポジトリで実行する。既存の5173番開発サーバーを維持するため、今回は専用ポート5175・18085を使用した。

```sh
npm run check
E2E_PORT=5175 E2E_API_PORT=18085 npm run test:e2e
E2E_PORT=5175 E2E_API_PORT=18085 npm run test:e2e:coverage
```

Node.js 24.21.0・npm 11.19.0、Vitest/coverage-istanbul 5.0.3、vite-plugin-istanbul 9.0.1、Playwright 1.64.0のChromiumで確認。PCは1440×900、スマートフォンは390×844。

| 保存先 | 内容 |
| --- | --- |
| `coverage/vitest/` | HTML・JSON・LCOVと未到達の文・分岐一覧 |
| `coverage/e2e/summary.md`・`summary.json` | PC・スマートフォン・合算、全体・重点範囲 |
| `coverage/e2e/{desktop,mobile,combined}/` | HTML・JSON・LCOV・未到達一覧。`priority/`が重点範囲 |
| `coverage/e2e/raw/` | シナリオ・文書ごとの生データ |

再読み込み前の結果をsessionStorageへ文書ID付きで保存し、pagehideと最終回収の重複を除いて集計する。再読み込みの前後でIDが変わり、前の文書が保存されていることをブラウザで確認。各テストは独立したブラウザコンテキストを使用し、実行開始時に前回の生データを削除する。

通常のdistは計測コードなし。計測専用成果物は`.coverage-dist/`へ分離する。GitHub ActionsはVitestの100%判定、通常E2E、計測付きE2Eを実行し、カバレッジ成果物を成功・失敗にかかわらず7日間保存する。生成レポート・専用ビルドはGit管理対象外。

専用APIスタブを使用し、実Go API・DB・FMP・LINEには接続していない。2026-10-13の実API・DB検証は別の記録として保持する。
